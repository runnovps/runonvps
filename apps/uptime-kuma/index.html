Quick start

Docker Compose quick start

A trimmed version of the Uptime Kuma file from our Self-host Starter Pack — same images and services, comments and extras removed. Every secret is an .env placeholder.

docker-compose.ymlquick-start version
services:
  uptime-kuma:
    image: louislam/uptime-kuma:2
    restart: unless-stopped
    ports:
      - "${UPTIME_KUMA_PORT:-3001}:3001"
    volumes:
      - uptime-kuma:/app/data

volumes:
  uptime-kuma:

Save it as docker-compose.yml, put the ${...} values in a .env file next to it, then run docker compose up -d. The pack version adds per-app setup notes, backup pointers and hardening checks.

FAQ

Uptime Kuma VPS questions

Answers use only the checked dataset on this page — estimates are called out as estimates.

What are the minimum VPS requirements for Uptime Kuma?

In the RunOnVPS dataset, Uptime Kuma needs at least RAM 512MB, CPU 1, disk 5GB. Some of these figures are estimated rather than officially published — the badge next to each value in the table above shows its basis. Our suggested starting tier, based on the recommended RAM, is the 1 GB RAM tier.

Does Uptime Kuma need a GPU?

No. Uptime Kuma does not need a GPU — the baseline deployment runs on CPU only.

What SaaS product does Uptime Kuma replace?

Uptime Kuma is catalogued here as a self-hosted alternative to UptimeRobot. Self-hosting replaces the hosted subscription with your own VPS; feature parity varies, so compare your required workflow before migrating.
