Quick start

Docker Compose quick start

A trimmed quick-start version of the official Jitsi Meet Docker deployment — same images and services, comments and extras removed. Every secret is an .env placeholder.

docker-compose.ymlquick-start version
services:
  web:
    image: ghcr.io/jitsi/web:stable
    restart: unless-stopped
    ports:
      - "${HTTP_PORT:-8000}:8000"
      - "${HTTPS_PORT:-8443}:8443"
    volumes:
      - ${CONFIG:-./jitsi-meet-cfg}/web:/config
      - ${CONFIG:-./jitsi-meet-cfg}/transcripts:/usr/share/jitsi-meet/transcripts
    environment:
      - PUBLIC_URL=${PUBLIC_URL:?Set PUBLIC_URL in .env}
      - XMPP_DOMAIN=${XMPP_DOMAIN:-meet.jitsi}
      - ENABLE_LETSENCRYPT=0
      - DISABLE_HTTPS=1
    depends_on: [prosody, jicofo, jvb]
  prosody:
    image: ghcr.io/jitsi/prosody:stable
    restart: unless-stopped
    volumes:
      - ${CONFIG:-./jitsi-meet-cfg}/prosody:/config
    environment:
      - XMPP_DOMAIN=${XMPP_DOMAIN:-meet.jitsi}
      - JICOFO_AUTH_PASSWORD=${JICOFO_AUTH_PASSWORD:?Generate with ./gen-passwords.sh}
      - JVB_AUTH_PASSWORD=${JVB_AUTH_PASSWORD:?Generate with ./gen-passwords.sh}
  jicofo:
    image: ghcr.io/jitsi/jicofo:stable
    restart: unless-stopped
    environment:
      - XMPP_DOMAIN=${XMPP_DOMAIN:-meet.jitsi}
      - JICOFO_AUTH_PASSWORD=${JICOFO_AUTH_PASSWORD:?Generate with ./gen-passwords.sh}
    depends_on: [prosody]
  jvb:
    image: ghcr.io/jitsi/jvb:stable
    restart: unless-stopped
    ports:
      - "${JVB_PORT:-10000}:10000/udp"
    volumes:
      - ${CONFIG:-./jitsi-meet-cfg}/jvb:/config
    environment:
      - XMPP_DOMAIN=${XMPP_DOMAIN:-meet.jitsi}
      - JVB_AUTH_PASSWORD=${JVB_AUTH_PASSWORD:?Generate with ./gen-passwords.sh}
      - JVB_PORT=${JVB_PORT:-10000}
    depends_on: [prosody]

Save it as docker-compose.yml, put the ${...} values in a .env file next to it, then run docker compose up -d. The Self-host Starter Pack versions (20 apps) add per-app setup notes, backup pointers and hardening checks.

FAQ

Jitsi Meet VPS questions

Answers use only the checked dataset on this page — estimates are called out as estimates.

What are the minimum VPS requirements for Jitsi Meet?

In the RunOnVPS dataset, Jitsi Meet needs at least RAM 2 GB, CPU 4 vCPU, disk 20 GB. Our suggested starting tier, based on the recommended RAM, is the 8 GB RAM tier.

Does Jitsi Meet need a GPU?

No. Jitsi Meet does not need a GPU — the baseline deployment runs on CPU only.

What SaaS product does Jitsi Meet replace?

Jitsi Meet is catalogued here as a self-hosted alternative to Zoom / Google Meet. Self-hosting replaces the hosted subscription with your own VPS; feature parity varies, so compare your required workflow before migrating.

Source check

Important notes

Official Jitsi handbook requirements (checked 2026-11-15): RAM 8 GB suggested, 4 GB for small meetings, 2 GB for test or very small meetings; basic server 4 dedicated cores; disk 20 GB standard disk (SSD nice to have, not required). Recording (Jibri) needs one separate system per recorded meeting and is not counted here. Official Docker deployment via jitsi/docker-jitsi-meet (web 8000/8443, JVB UDP 10000).
