Quick start

Docker Compose quick start

A trimmed quick-start version of the official Stirling-PDF Docker deployment — same images and services, comments and extras removed. Every secret is an .env placeholder.

docker-compose.ymlquick-start version
services:
  stirling-pdf:
    image: stirlingtools/stirling-pdf:latest
    restart: unless-stopped
    ports:
      - "${STIRLING_PORT:-8080}:8080"
    volumes:
      - ./data/trainingData:/usr/share/tessdata
      - ./data/configs:/configs
      - ./data/logs:/logs
    environment:
      SECURITY_ENABLELOGIN: ${SECURITY_ENABLELOGIN:-false}
      LANGS: ${LANGS:-en_GB}

Save it as docker-compose.yml, put the ${...} values in a .env file next to it, then run docker compose up -d. The Self-host Starter Pack versions (20 apps) add per-app setup notes, backup pointers and hardening checks.

FAQ

Stirling-PDF VPS questions

Answers use only the checked dataset on this page — estimates are called out as estimates.

What are the minimum VPS requirements for Stirling-PDF?

In the RunOnVPS dataset, Stirling-PDF needs at least RAM 2GB, CPU 2, disk 5GB. Some of these figures are estimated rather than officially published — the badge next to each value in the table above shows its basis. Our suggested starting tier, based on the recommended RAM, is the 4 GB RAM tier.

Does Stirling-PDF need a GPU?

No. Stirling-PDF does not need a GPU — the baseline deployment runs on CPU only.

What SaaS product does Stirling-PDF replace?

Stirling-PDF is catalogued here as a self-hosted alternative to iLovePDF. Self-hosting replaces the hosted subscription with your own VPS; feature parity varies, so compare your required workflow before migrating.
