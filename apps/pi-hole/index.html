Quick start

Docker Compose quick start

A trimmed quick-start version of the official Pi-hole Docker deployment — same images and services, comments and extras removed. Every secret is an .env placeholder.

docker-compose.ymlquick-start version
services:
  pihole:
    image: pihole/pihole:latest
    restart: unless-stopped
    ports:
      - "53:53/tcp"
      - "53:53/udp"
      - "80:80/tcp"
      - "443:443/tcp"
    environment:
      TZ: ${TZ:-Europe/London}
      FTLCONF_webserver_api_password: ${PIHOLE_PASSWORD:?Set PIHOLE_PASSWORD in .env}
      FTLCONF_dns_listeningMode: 'ALL'
    volumes:
      - ./etc-pihole:/etc/pihole

Save it as docker-compose.yml, put the ${...} values in a .env file next to it, then run docker compose up -d. The Self-host Starter Pack versions (20 apps) add per-app setup notes, backup pointers and hardening checks.

FAQ

Pi-hole VPS questions

Answers use only the checked dataset on this page — estimates are called out as estimates.

What are the minimum VPS requirements for Pi-hole?

In the RunOnVPS dataset, Pi-hole needs at least RAM 512MB, CPU 1, disk 2GB. Some of these figures are estimated rather than officially published — the badge next to each value in the table above shows its basis. Our suggested starting tier, based on the recommended RAM, is the 1 GB RAM tier.

Does Pi-hole need a GPU?

No. Pi-hole does not need a GPU — the baseline deployment runs on CPU only.

What SaaS product does Pi-hole replace?

Pi-hole is catalogued here as a self-hosted alternative to NextDNS. Self-hosting replaces the hosted subscription with your own VPS; feature parity varies, so compare your required workflow before migrating.
