Quick start

Docker Compose quick start

A trimmed quick-start version of the official RustDesk Docker deployment — same images and services, comments and extras removed. Every secret is an .env placeholder.

docker-compose.ymlquick-start version
services:
  hbbs:
    container_name: hbbs
    image: rustdesk/rustdesk-server:latest
    command: hbbs
    volumes:
      - ./data:/root
    network_mode: "host"
    restart: unless-stopped
  hbbr:
    container_name: hbbr
    image: rustdesk/rustdesk-server:latest
    command: hbbr
    volumes:
      - ./data:/root
    network_mode: "host"
    restart: unless-stopped

Save it as docker-compose.yml, put the ${...} values in a .env file next to it, then run docker compose up -d. The Self-host Starter Pack versions (20 apps) add per-app setup notes, backup pointers and hardening checks.

FAQ

RustDesk VPS questions

Answers use only the checked dataset on this page — estimates are called out as estimates.

What are the minimum VPS requirements for RustDesk?

In the RunOnVPS dataset, RustDesk needs at least RAM 512 MB, CPU 1 vCPU, disk 2 GB. Some of these figures are estimated rather than officially published — the badge next to each value in the table above shows its basis. Our suggested starting tier, based on the recommended RAM, is the 1 GB RAM tier.

Does RustDesk need a GPU?

No. RustDesk does not need a GPU — the baseline deployment runs on CPU only.

What SaaS product does RustDesk replace?

RustDesk is catalogued here as a self-hosted alternative to TeamViewer / AnyDesk. Self-hosting replaces the hosted subscription with your own VPS; feature parity varies, so compare your required workflow before migrating.

Source check

Important notes

Official Docker docs (checked 2026-11-03) publish no hardware minimum: they require only Docker/Podman and the firewall ports (hbbs 21115/21116 TCP+UDP, 21117 relay; Pro console 21114 not in OSS). Estimates are for the two tiny binaries hbbs (ID/rendezvous) and hbbr (relay) from the official rustdesk/rustdesk-server image with network_mode host and a shared ./data volume holding the generated key pair; relay bandwidth, not RAM, is the real sizing input.
